# 并击击键当量（chordtype-timing）— 并击（多键同击）击间当量建模

> **命名说明（2026-10-12 建仓）**：GitHub 仓库 = 英文名 **`chordtype-timing`**，中文名 = **并击击键当量**。
> 本机 OneDrive 目录 `d:\OneDrive\typing\并击击键当量\` = **规范源**（先在此编辑），
> `D:/chordtype-timing` = **发布副本**（由 `sync_github.py` 同步推送，见 §8.3）。
> 本文中形如 `§5.1` 的引用一律指向**本 README 的章节号**。

**摘要**：本项目从个人并击（多键同击）打字实测数据中学习**组合 → 组合**的击间转移当量：每手建"组合 → 组合"转移表，双手合成取 `max(左右手链)`。核心设计是把每手在二字词内的占用**精确分解为三段**——`wc_h = S1_h + S2_h + S3_h`（S1/S3 = 该击本手占用、S2 = 换手间隙），于是只需两张表：**occ 表**（组合 → 击内占用；1 击试次的孤立角色与 2 击试次的 S1/S3 共享同一组合基数）与 **gap 表**（组合 → 组合的换手间隙；79² 键对空间极稀，由 8 维几何先验 φ 与键对中位收缩撑起）。当量为 **ms 期望耗时原值**（默认不含错误项），与姊妹项目串击（[`better-keystroke-timing`](https://github.com/zhanghaozhecn/better-keystroke-timing)）同用户、同单位、可直接对比。当前快照（采集 5,320 行 / 32 session；单手 79 组合采样空间；左右 1:1 随机单手混采）固定 trial 测试集 MAE：段-occ **11.9(l) / 12.9(r)** ms、段-gap **18.3 / 17.0** ms、1 击词 **10.2 / 9.9** ms、2 击词 **26.6 / 26.1** ms；三段分解相对"直接预测整击耗时"的净收益 **+10.7 / +10.3** ms。全部口径（组合空间、TSV 格式、三段量、阈值与 σ、错误成本常数）由 `并击公共.py` + `采集核心.py` 单点定义，其余脚本一律 import 复用。

**关键词**：并击打字；多键同击；击键当量；条件段模型；个人化建模；输入法编码方案评估；表格数据回归

## 1. 引言

**并击**（chord typing，多键同击）以"同时按下的一组键"为输入单位：一击由左手 0–2 键与右手 0–2 键组成，全部放开时由输入法引擎（本项目的规则样例 = 拼读并击，RIME `chord_composer`，说明书 251223）输出该击对应的多码。方案层面：声介 51 组合（左手）× 韵调 44 组合（右手），一击 = 声介码 + 韵调码 = 2 码 = 一个带调音节，**一个二字词 = 两击 = 4 码**。与顺序击键（串击）相比，并击把"手回位再按下一键"的串行结构换成了双手并行 + 击内异步，理论键入效率更高，代价是击内同步约束、换手间隙与更重的读图/计划负担——这些代价到底值多少 ms，是键位设计与方案间对比的必答题。

键位成本模型传统的做法是**2 键当量逐对累加**（`T'(abcd) = B(a,b) + B(b,c) + B(c,d)`），其隐含假设"打完一个键手就回静止位"。姊妹项目串击已用同用户数据实测该假设系统性低估整串耗时（跨手 +32ms → 同手异指 +86ms），足以让约 20% 的方案排序被扭曲。并击还有第二条传统工具处理不了的结构：**双手并行 ⇒ 两击之间存在闸门**（慢手全放门控下一击），单手表不能简单相加。本项目因此不用"键对表"，而以**单手组合**为原子单位、以**条件转移**为建模对象。

方法上有三个决定性的选择。① **三段分解**：单手在二字词内的占用可精确分解为 `S1 + S2 + S3`（同试次锚点直接给出，望远镜求和恒等），其中 S1/S3 与"孤立单击占用"是同一个量（`occ`），只有换手间隙 `S2` 是新的量——于是 1 击试次的数据直接成为 2 击模型的基线，采集量减半而口径统一。② **手独立 max 分解**：双手合成取 `max(左右手链)`，闸门项经 550 万真实词全枚举证明恒为 0（§5.2），不可测的残差只落在"手独立 + 预放置吸收度"上，合成因而是**下界方向**。③ **几何先验 φ**：79² 的击对空间在可行预算内只能观测约 1% ，因此 gap 表以"两击之间的几何变化量"（行向位移、键重叠、负载四格等 8 维）作 ridge 先验，键对样本向它收缩——这是"未见键对外推"的全部来源。

主要贡献：

- **并击的对称段模型**：单手三段分解 + 手独立 max 合成 + 闸门项的实测零化（§4.1、§5.2-36/37），把 2 击词当量化为两张表的组合；
- **两阶段建模**：occ 侧 = 组合 onehot ridge 先验 + 键级中位收缩（`log occ = base(组合) + offset(角色)`）；gap 侧 = 8 维几何 φ 先验 + 键对中位收缩（§4.3）；
- **几何先验 φ v8**：负载由 max 主导、必须写成列数对四格（1→2 与 2→1 不可加），|Δ行| 是全表最稳的一维（+11.0%/行），键重叠是唯一负向维（−14~−16%）——逐维系数与删除依据见 §4.3.1；
- **组合空间的精确结构**：63 双键 = 9 指对 × 7 行对的笛卡尔积、occ 的方差由指对主导（94–95% 可加），并由此得到稀疏组合的外推方案（§5.2）；
- **数据协议与剔除判据**：左右 1:1 随机单手混采（练习效应对称）、序号块稳定期边界、双判据剔除（难度异常 / 配额选码）与"双手交集"动作集（§3、§4.4）；
- **全部口径的闭环自测**：段级/组合级留出的门禁单元、合成数据植入真值的自测（`--selftest`）、采集 GUI 冒烟（`--smoke`）。

本文档组织：§2 相关工作与并击/串击的结构差异；§3 数据（打字模型、采集协议、格式、稳定期）；§4 方法（当量构造、模型、剔除、评估协议、组装）；§5 结果；§6 讨论；§7 结论与应用；§8 复现（命令链、产物、目录、分发）；§9 文档分工；参考文献与附录。

## 2. 相关工作与结构差异

**同源工作——串击条件段模型**：[`better-keystroke-timing`](https://github.com/zhanghaozhecn/better-keystroke-timing) 用同一套哲学处理顺序击键，以"对称条件段"`S(p,a,b,n)` 为单位建模，2/3/4 键当量同源。本项目是它的并击对应物：**划分、剔除、复现与报数口径全部继承该项目**（trial 级划分、MAD 单侧围栏、四宫格、MAE/R² 并列、跨快照只比 MAE、固定种子全体平均），差异只出现在击的结构上。

**传统 2 键当量表与键位优化工具**：陈一凡 1986 的 46 键两键当量表是中文键盘评估的经典数据（群体平均）；Carpalx、keygen 类工具以 2 键表逐对累加作为目标函数。本项目与它们不是同一量：这里报的是**个人**在当前熟练状态下的 1 击词/2 击词期望耗时（ms 原值，不归一化），且显式建模键对间的条件依赖。

**并击/chord 键盘研究**：既有工作多关注可行性、学习曲线与输入速度上限（两手手指组合的记忆与教学成本），少有"逐组合时间当量表 + 可外推的几何先验"这一层。本项目服务对象 = 拼读并击方案（RIME `chord_composer`），但不承担任何具体方案的覆盖约束：模型是通用的（79 组合/手），方案只是它的一个用量。

两个项目在结构上的差异（也是"同一套当量哲学能否搬过来"必须先回答的问题）：

| 维度 | 串击（击键测速） | 并击 |
|------|-----------------|------|
| 基本单元 | 键 | 击（1-4 键同按集合，一击 2 码） |
| 双手关系 | 交替 | **并行**（每击双手同时发力） |
| 单元内部结构 | 无 | 击内散布（同击首末按下异步）+ 跨手同步约束 |
| 串行约束 | 无需释放 | 下一击前必须全放（慢手门控） |
| 错误模式 | 错键/退格 | 整击失败（错键/缺键/失同步）；退格清全部编码 |
| 词边界 | 注意力中断，不计词间当量 | **同理不计**（口径划界一致） |

不变的核心判断：**时间成本住在"转移"里**——串击测键对转移，并击测击对转移。

## 3. 数据

数据全部来自单人（作者本人）在本机 GUI 采集器上的照图转录任务：屏幕显示键位图、按亮键击打、精确记录每击每手四个时间锚点。采集与分析的**唯一数据源**是项目根 `当量数据.tsv`（22 列，§3.4）；练习模式的数据另存 `练习数据.tsv`，不进模型。

### 3.1 并击的打字模型（事实层）

#### 3.1.1 击的定义与引擎语义

- **击（stroke）= 左手并击组合（0-2 键）+ 右手并击组合（0-2 键）**：以任意顺序按下、
  任意顺序放开，**全部放开时触发键位映射**（输出多码）。左手 15 键 `qwertasdfgzxcvb`，
  右手 15 键 `yuiophjkl;nm,./`，拇指空格可并入击（v1 不采）。
- RIME `chord_composer` 语义（schema 实测确认）：同按（按键时间上重叠）为一击，
  全放时输出。推论：
  - 同击所有键的按放窗口必须互相重叠，否则引擎拆击/提前输出缺键击
    → **快手必须 hold 等慢手落下**（击内跨手同步约束，§6.2）；
  - 下一击任何键按下时上一击必须已全放（否则并回同一击）→ **慢手全放门控下一击**。
- **击是无序键集合**（哪指先落因人而异），存储 canonical 序（左手键盘序+右手键盘序）。

#### 3.1.2 两击 = 4 码 = 一个二字词

- 拼读并击：声介 51 组合（左，12 单+39 双）× 韵调 44 组合（右，14 单+30 双），
  一击 = 声介码+韵调码 = 2 码 = 一个带调音节；**二字词 = 两击 = 4 码**。
- 标准字词并击方案的词内击序列就是两击；3+ 字词（3 击）是少数派近似处理（§6.2）。
- 其余击型（选重/标点/部首）均为单手击，作为两击对的成员进入同一套表。

### 3.2 采集协议与试次模式

- **试次随机混采，比例 1 击 : 2 击 = 1:4**（临时档，2026-10-11 用户决策：gap 段样本量是当前瓶颈，2 击试次产出 gap 行 ⇒ 提高其占比；回退条件写在 `并击公共.MIX_ONE_TWO` 常量注释里，改回 1:2 是数据侧零改动的常量调整）。
  - **2 击试次**（= 4 码 = 一个二字词）：给出词占用 `wc` 与三段 `S1/S2/S3`；
  - **1 击试次**（= 2 码 = 一个一击词/一级字/简词）：给出**孤立角色** `occ = fd→lu` 与孤立散布，既是模型 occ 表的 1 击词部分，又是"从静息起手、无上文"的基线，与 2 击试次的 S1/S3 对照可量化上文效应。
  两类试次交替还天然打断节律；试次间随机延迟 300-800ms。
- **采集手 = 左右 1:1 增补混采**（2026-10-01 起为唯一模式）：每试次按累计欠账抽边（`并击公共.hand_probability`：基础份额 1:1 + 欠账偏置，单侧概率夹在 [0.18, 0.82]）⇒ 落后的一侧被增补、两侧始终交错（**练习效应对称**，这是"必须同时采两手"的核心目的）。无固定单手模式：方案要求左右可用组合对称（§4.4 的双手交集动作集），固定单手会让另一手没有同期数据、并把练习效应与手别效应混在一起。手内协议不变（混采比、结构权重、多样性、降权系数），各手独立计数池。
- **数据实时落盘**：每完成一个试次立即追加写入 tsv（`trial`/`session` 可溯源），没有"结束才保存"；Esc 随时退出（未完成试次不入库）。
- **采集工作流**（顺序）：① 直接开始正式采集（无熟化前置，练习段由稳定期方法统一切除，§3.5）；② 每 ~500-1000 试次跑一次剔除审阅（`分析-难度剔除.py --dry-run` / `--judge quota --dry-run`，§4.4），命中的组合由两张动作表即时退出采样空间；③ 数据足够后重跑建模与组装（§8.1）。
- **不采集"双手同击"**（2026-09-07 决策）：双手一次的信息解析量大、练习成本高，练不出稳定数据。与左右 1:1 不冲突——每次试次仍是单手击（手独立 max 分解不变），只是试次流在两手间交替。由此双边合成的残差**不可实测**（见 §6.2-1）。

#### 3.2.1 输入层：无视输入法的按键捕获（v2.47/v2.48）

输入法中文态下，字母先被 IME 拿去组字 ⇒ tkinter 的 `<KeyPress>` 只带 `keysym='??'` / `char=''`，采集器会判定"没有按键"（整场收不到；本机 zh-CN 实测，`space` 甚至变成 `减`）。现行输入层只有一条机制：

- **摘除窗口 IME**（`ImmAssociateContext(hwnd, NULL)`，`采集核心.ime_detach`）：本窗口没有输入上下文 ⇒ IME 不参与，tkinter 直接收到干净字母，不组字、不输出编码、不弹候选框。窗口每次激活后与每 2 s **重摘**一次（系统会在激活/切换输入法后重新关联，tkinter 获焦时也会自己挂上下文）。
- **按键来源 = tkinter 事件绑定**（`on_press`/`on_release` ← `root.bind("<KeyPress>"/"<KeyRelease>")`），键名取 `event.char` 的小写（`Escape` 走 keysym，松开事件 char 为空时用 keysym 兜底）。
- **排障开关 `--no-ime`**：整体关掉输入层（回到修复前行为）——用于现场 A/B 证明这层在起作用、二分定位"打字没反应"、以及换机器时的逃生。它**不改事件源与时间戳取法、也不改落盘列 ⇒ 两种模式数据同口径**。
- **另两层已删除**（设计史存档于 `memory/bingji-timing.md`）：低层键盘钩子 `WinKeyHook`（v2.47 删，代价是一整套全局钩子 + 消息泵 + 全局吞键，而"摘窗口 IME"实测已够）与进程级 `ImmDisableIME(0)`（v2.46 删，只禁调用线程且时序脆弱）。
- **⚠ 计时口径的界**：v2.47 把时间锚点从"钩子回调内取 `perf_counter`"改为"tkinter 事件处理内取"。**试次内所有锚点同源**（段内相对时序不受影响，当量口径不变），但两版主循环延迟特性不同 ⇒ **跨这次改动不要比亚毫秒差**。

### 3.3 分击校验与错误记录

| 规则 | 触发 | 含义 |
|------|------|------|
| R1 键序错误 | 按下的键 ∉ 当前击剩余键集 | 键序/多按/按了另一手的键 |
| R2 散布超限 | 同击首末按下间隔 > T_SYNC | 失同步（并击失败） |
| R3 提前击 | 上一击成形但未全放时按下新键 | 引擎并回同一击 |
| R4 击不完整 | 已按键全部释放但击缺键 | 引擎输出缺键击（击内断开亦在此刻判定） |

- **错误全部落盘**：`error=1` + `err_type`（`规则@击序`）+ `actual`（实际输入，含出错键；
  出错键先落盘再校验——否则无从复原"按了什么"）。错误试次也记录已发生的锚点（部分），
  但**不进当量**（§4.1/§4.4），也不占用采样覆盖计数（占覆盖会让易错转移欠采样）。
- **按键残留防护**：GUI 维护物理按下键集（跨试次），已按下键的重复事件（Windows 自动重复，
  出错后仍按住键时尤其常见）不计为新按键 → 否则会产生伪 R1 错误。

错误试次照记（error=1 + actual）供错误率建模。T_SYNC = 100ms（v1 常量，M1 校准 80-120）。

### 3.4 数据格式（`当量数据.tsv`，22 列）

`code | 16 锚 | error | err_type | actual | trial | session`

- code = 击串以 `|` 连接（击串 = 左手键键盘序 + 右手键键盘序）：
  **2 击行**如 `sf|xc`（二字词）；**1 击行**如 `sf`（一击词/孤立组合，无 `|`）；
- 每击每手四锚 fd/ld/fu/lu（ms，相对本试次首按；该手该击无键 = 0.0，错误试次缺失填 0）；
  **1 击行的二击 8 列为 0.0**、单模式采集的非活动手列为 0.0（列数恒 22 = code +
  16 锚 [2 击 × 2 手 × 4] + 5 元数据）；
- **错误记录三要素**（2026-09-07 补齐）：
  - `error` = 0/1；
  - `err_type` = 错误短标签 **`规则@击序`**（`R1@1` 键序错误 / `R2@2` 失同步 /
    `R3@1` 提前击 / `R4@1` 缺键；正确行为空）——由状态机在触发点直接落盘，
    不靠事后反推（旧的反推法会把 R3 误判成 R1）；
  - `actual` = **用户实际输入**（含出错键本身：R1 记下按错的键、R2 记下超限键、
    R3 记下抢跑键、R4 记下已按子集）——出错键先落盘再校验，否则无从复原；
- 派生量全部可由锚点重构：
  2 击行 → S1 = lu1−fd1、S2 = fd2−lu1、S3 = lu2−fd2、wc = S1+S2+S3；
  1 击行 → occ = lu1−fd1、spread = ld1−fd1。
- **文件路径口径（2026-09-24）**：所有数据/排除表路径 = **脚本所在目录**
  （`BASE = Path(__file__).resolve().parent`），不硬编码绝对路径、**与 CWD 无关** ⇒
  整个项目目录可任意迁移/改名，采集与分析始终同源（曾有一处硬编码 OneDrive 绝对路径：
  目录一改名，采集会静默写到旧路径而分析读不到）。`实验/` 脚本路径 = 项目根（上一级）。

### 3.5 稳定期：分类型计算

- **两类试次时间尺度不同**（1 击 ~200ms 级 vs 2 击 ~400ms 级）→ 混在同一时间序列里
  切块会污染块中位；**各自跑序号块边界**（`并击公共.stable_by_type`）：
  边界指标 = 1 击行的 occ / 2 击行的 wc。
- **少数类样本不足以自成边界时按主类稳定起点同截归属**（姊妹项目做法：少数类型不参与
  边界计算，按时间序自稳定起点同截）。判据：该类试次数 ≥ 8 块 × BLOCK(100) 才有自己的
  边界，否则借主类的全局截断行号。
- 方法（确定性，无随机，移植自击键测速 §4.3.1）：ok 行按序切等大块 → 块内指标中位 →
  3 块滚动中位平滑 → R = 末 5 块平滑值中位 → 自末向前最早连续满足 ≤R×1.10 的块起 = 稳定期。
- 2 击类**另跑三段（S1/S2/S3）各自边界**（hold 与重定位的熟练曲线可能不同，诊断用）。
- `分析-熟练度.py` 一次打印全部：分类型 method/cut_row/稳定期规模 + 三段边界 + 漂移幅度。
- 建模与难度统计只用稳定期数据（当量 = 当前状态语义）；session 不参与（进程生命周期，
  不携带状态信息——**序号优于 session**，姊妹项目 2026-09-06 定论）。

## 4. 方法

### 4.1 当量构造：时间锚、建模范围与三段分解

#### 4.1.1 时间锚：lu（全放）+ fd（词首）

编码进入输入法解析的时点 = 全放时刻 lu（每击每手记 fd/ld/fu/lu 四锚，ms，相对试次首按）。
**lu = 击间/击内主锚**（语义即"下一码何时可用"）；**fd₁ = 词首锚**（词占用的起点）；
fd 兼作诊断锚（散布分析、与串击按下锚衔接）。

#### 4.1.2 建模范围：词占用当量（v2.4 修订）

- **词当量 = 词占用语义 = fd₁ → lu₂**（从首击首按到末击全放，末码进解析）；操作性定义
  = **闸门感知合成**（§4.1，同时起手；2 击词 = **max_h 手链**，闸门项实测恒 0，v2.33）。
  一击词 = max(该手单击占用 occ)，有定义（原 lu₁→lu₂ 口径下一击词当量为零、"免费"输出，已废弃）。
- 词间注意力中断（读词/构思/选重），与串击不计词间当量同一原理，**不建模**；
  时间轴分割无重叠无缝隙（词占用 + 词间缺口）。
- 前击条件（P₋₁）在标准两击字词方案中**结构上不存在于词内**——只可能出现在词间（不建模）
  或 3+ 字词的第二对（§6.2 近似处理）。无需消融，直接不需要。

#### 4.1.3 三段分解口径（v2.6）：单手 wc = S1+S2+S3，复用单击数据

每只手在二字词内的占用**精确分解为三段**（恒等式，无新增列）：

```
wc_h = S1_h + S2_h + S3_h            （同试次锚点直接给出，望远镜求和恒等）
  S1_h = lu1_h − fd1_h    第一击本手占用（成形 + hold + 释放）≡ occ_h(c1)
  S2_h = fd2_h − lu1_h    换手间隙（本手释放 → 本手下一击首按）
  S3_h = lu2_h − fd2_h    第二击本手占用 ≡ occ_h(c2)
```

```
模型 A（occ 表）: occ_h(组合)   ← 1 击试次（孤立角色）+ 2 击试次的 S1/S3（段位偏移）
模型 B（gap 表）: gap_h(c1→c2)  ← S2（手内 79² 对，纯移动量 → 几何 φ 外推）
                  ★ 用单手数据（本征间隙）训练；闸门只在合成时施加（见下）
词当量 = 闸门感知合成（同时起手）:
  2 击词: max( max_h(occ(c1)+gap+occ(c2)),  max_h(occ(c1)) + max_h(occ(c2)) )
  n 击词: 逐击 max-plus 传播  G_k = max_h(lu_k,h);  fd_{k+1},h = max(lu_k,h + gap_h, G_k)
```

- **相位视角**：第 1 段 max（慢手定相）、第 2 段起点由闸门与最早就绪手取较晚者、
  第 3 段终点 max——**不是简单 max_h(wc_h)**（见下条 2026-09-07 二次修正）。
- **复用（核心收益）**：S1/S3 即"首键按下→尾键放开"，与模型 A 同一个量——1 击试次供
  孤立角色**基线**（原地同状态），2 击试次的 S1/S3 供**段位偏移**
  （词首/词尾的上下文预备效应；先例：击键测速段位特征 φ19+6 角色片已落地）；
  只有 S2 需要新对表。
- **S2 是纯移动量**（释放组合 → 按下组合的重定位）：几何 φ（跨度变化、同指跨行、
  手内位移）外推能力远强于混合量 wc——分解的主要数据效率来源。
- **推广**：3+ 击词按逐击 max-plus 传播（闸门项自然纳入，不再是近似）；标点/选重击
  同样复用 occ；一击词与二字词共用 occ 表 → 两者预测在公共部分自动一致。
- **组合规则（模拟口径，2026-09-07 二次修正）**：单手表合成双手时**必须显式施加闸门**
  `fd2_h ≥ max_h lu1_h`——单手数据里的 S2 是**无闸门的本征间隙**，而双手打字时快手的
  第二击会被慢手的第一击释放挡住（用户反例：S1_R+S2_R < S1_L 时 R 必须等闸门）。
  同时起手假设下 2 击词**闭式**：
  ```
  word = max( max_h(S1_h+S2_h+S3_h) ,  max_h(S1_h) + max_h(S3_h) )
                    └ 无阻塞项（= 本征 max wc）    └ 闸门阻塞项（= 慢手首段 + 慢手末段）
  ```                                                    ↑ v2.33 实测: 恒 ≤ 左项 ⇒ 2 击词 = 左项
  两项**都由单手表算出** → 降维保持（只是从一项变两项）。n 击词 = 逐击 max-plus 传播：
  `G_k = max_h(lu_k,h)`（闸门开启 = 该击最后一键释放）、`fd_{k+1},h = max(lu_k,h + S2_h, G_k)`。
  量级示例：S1_L=200/S2_L=50/S3_L=100、S1_R=50/S2_R=20/S3_R=400 → 真值 600
  （= S1_L+S3_R），naive max wc = 470，**低估 130ms**。
- **v2.33 简化: 2 击词 = `max_h(S1_h+S2_h+S3_h)`, 闸门项恒为 0**:
  上例是"闸门项 binding"的**构造情形**, 实测表上从不发生 —— 闭式
  `Δ = F − D = max(0, min(S1_A−S1_B−gap_B, S3_B−S3_A−gap_A))`（A/B = S1/S3 支配手）,
  为正要跨过**另一只手的本征间隙**; 而 (实验/实验-分段max合成.py) 拼读并击在用组合
  **全枚举 5,035,536 个二字词 (声介 51 × 韵调 44 的两击) Δ ≡ 0**（最险词余量 48.7ms;
  三级字最紧 16.4ms; bootstrap 重采样重训 60 轮 0 翻转）—— 因为**跨手段差 (~50–70ms)
  < gap (~63–170ms)**。⇒ 生产 `compose_word` 2 击分支直接取 `max_h 手链`（≡ 原式, 少算一项）;
  **⚠ 守卫**: 若 3 键组合进方案 / 某手系统性更慢 / 某格 gap 变小 ⇒ 重跑 `--part 3`,
  出现 Δ>0 就恢复闸门项。不可测的残差**不是**闸门项（它恒为 0）, 而是"手独立 + 预放置吸收度"（§6.2-1）。
- **架构推论**：gap 表必须用**单手数据（本征间隙）**训练，闸门只在合成时施加；
  用带闸门的数据训练会把等待烘焙进表、合成时双重计数。
- **起手假设**：模拟时按**同时起手**（用户 2026-09-07 指定）——把量级更大的闸门阻塞项
  精确处理掉，代价是忽略起手异步（真实打字中 ms 级、单侧）。
- **双手实测口径已不采用**（2026-09-07 决策，§3.2）：both 采集移除后，
  "实测 S2 已被闸门抬高 → 恒等式 `word = max_h(a_h+wc_h)`" 这条仅作原理备查；
  起手异步与预放置吸收度**不再实测**（记入 §6.2 残差）。
- **分解是结构先验，非既定收益**：三段分解 vs 直接预测 wc 的净收益需 M2 结构消融判定
  （姊妹项目教训：结构变体差常落在 ±1-2ms 噪声内，须用 trial 级固定测试集）。

#### 4.1.4 嵌入原子：单手键位组合

- 表/模型的原子单位 = **单手组合**（不是单键、不是双手击）：组合内键的交互
  （张指难度，如 SD 与 ZV 的差异超出线性叠加）由组合级嵌入自由捕捉。
- 采样/建模空间 = 每手 **79 个组合**（15 单 + 63 双 + **1 参考**）——**脱离具体方案**：
  拼读并击的 51/44 只是子集，键位重排后的新组合已在域内。合法性 = 物理可实现性
  约束（2026-08-19 实测反馈）：**① 单指一键**——同一手指键区内只能取 1 键
  （如左食指 r/t/f/g/v/b 任两键不可能同按）；**② 跨行 ≤1**——两键行距 2 几乎
  不可按（如 q+x、z+w）。约束外组合从采样与嵌入空间剔除（几何外推仍可覆盖）。

### 4.2 击内散布与错误项口径

- 击内散布（同击首末按下异步）与成形时间**归入手内链内部**（链 = 释放→回位→成形→释放），
  不单列副当量；fd 锚保留供诊断分解。
- **错误项默认不计入当量（v2.15, 2026-09-24 用户决策）**——当量 = **纯击键时间**：
  采集本质是**照图转录**任务（照键位图打，不涉及方案记忆），实测错误结构说明了它的性质：
  **34 个错误里 30 个是 R1（按错键）= 88%，且 27/30 落在第二击**；运动型（R2 失同步 /
  R3 提前击 / R4 缺键 = "没按成一击"）只有 4 个（12%）。R1 的成因是**没读对键位组合**
  （读取/计划错——第二块键位图要在击间间隙里读，工作记忆负荷最大），**不是按键失手**；
  真机使用并击时按键错误率低（用户 2026-09-24 实测判断）⇒ 转录任务测得的 P_err
  **不代表真机错误率** → 错误项暂不计入，`组装当量表.py --cost <ms>` 可随时打开。
- **错误记录照旧全量保留**（`error`/`err_type`/`actual`，见 §3.3/§3.4）：它不进食当量，
  但仍是诊断资产——机制分布、落点（iso/S1/S3×击序）是"读图负担"与"同步难度"的直接证据。
- **机制性质区分（决策依据）**：
  | 机制 | 语义 | 与并击当量的关系 |
  |---|---|---|
  | R1 按错键 | 读取/计划错（转录任务下的主要成分） | **不代表真机**；当量暂不计 |
  | R2 散布超限（失同步） | "没按成一击" | 运动型；若打开错误项才是相关的成本 |
  | R3 提前击（未全放就按下一击） | 抢跑 | 运动型 |
  | R4 击不完整（缺键/提前松手） | 漏键 | 运动型 |
- **若将来打开错误项（保留的完整口径）**：`错误当量 = Σ_击 P_err × ERR_COST_MS`，其中
  - **P_err 侧：已全量 instrumented** —— 每行有 `error` / `err_type`（`规则@击序`）/
    `actual`（含出错键本身），可按**组合、角色（S1/S3/孤立）、机制**分组建模。
    口径单位 = **每击一次机会**，且**错误后试次即中止 → 记到的是首个错误** ⇒ P_err 是
    **首错风险**（P(错@1)、P(错@2 | 第1击无错)），不是各击独立的错误率；
    每词期望 episode 数 = 1 − P(两击全对)（串击那边同构：错键处截断、键对按段位记账）。
  - **错误成本侧：指定常数 `ERR_COST_MS = 782.2ms`**（姊妹项目串击实测净成本的移植锚,
    n=278; 本 README 早期引的 879ms 是更早的小样本值）。**不自测的理由**：① 不可分解
    （纠错是整任务行为，无按键时间那样的可加链式分解 → 单手推不出双手纠错）；
    ② 直接测双手键位图串的读图/纠错成本过高（工具降级 `实验/`，见 §4.2）。
  - **常数口径的代价 = 必须报敏感性**：`组装当量表.py --cost {0,400,782,1000,2000}`
    各算一遍并报区间（2026-09-24 实测: 2 击词 395 / 462 / 527 / 563 / 732 ms）。
  - **真机错误率**只能靠连续文本录入测（与词间中断同源，§6.2）——本协议的试次是随机延迟
    触发的独立组，没有自然词间缺口。

- **错误率模型 v2（2026-10-11 用户决策"按建议重建"；`分析-错误率.py`）**：读取/运动
  **分头**建模 —— R1 与 R2-R4 首错机制互斥 ⇒ `p_err = p_r1 + p_mot` **精确**（不是近似）；
  每头 5-fold 事件级 AUC 选型（0.01 噪声带内取最简）。协变量 = 段位(iso/S1/S3) + 键数 +
  几何 φ(行距/列距/span/同列) + 练习位(试次全局序) + 另一击键数。**两头的特征画像不同**，
  这正是分头的依据（数据 5252 行 / 8679 击级机会 / 436 首错）：

  | 特征 | 读取型 R1（m4+练习, AUC 0.649） | 运动型 R2-R4（m3+几何, AUC 0.746） |
  |---|---|---|
  | 段位 S3 vs iso | **+1.29（最强）**: P 1.2%→4.4%（≈+24ms/击） | **+1.29**: P 1.0%→3.4%（≈+19ms/击） |
  | 段位 S1 vs iso | +0.43 | −0.30（比 iso 还低） |
  | 键数（每 +1） | −0.12（无关） | **+1.12（最强显著）**: 0.29%→0.71%→1.84% |

#### 4.3.1 生产 gap 先验 φ v8 详解（MODEL_VERSION 8）

历史候选 v5/v6/v7 的逐版演变见本机 `AGENTS.md`）

```
φ v8（生产, MODEL_VERSION 8）= 8 维:
  [ |Δ行|, Δ行(带号), 键重叠(0/1, 集合交), 列数对(1→1)(1→2)(2→1)(2→2) onehot, 1 ]
    Δ行 = 两击**键心**（组合全部键位置的行均值）之差, r₂−r₁（负=向上移, 正=向下移）;
    键重叠 = set(c₁)∩set(c₂) ≠ ∅（二元; 细分 1键/2键/整击 已测被否 — rare 格稀释）;
    列数对 = (n'₁, n'₂) 四格, n' = 键数且 **3 键计 2**（sdf/jkl 的 gap/occ ≈ 2键组合）

模型（生产 `ShrunkModel` gap 侧）:
  ① 先验: log gap ~ ridge([1]+φ, λ = 1.0)   ⚠ [1] 与 φ 末位常数共线,
     有效截距 = w[0] + w[-1]（λ 下分摊任意, 和唯一 — 读系数表必须相加）
  ② 收缩层: gap(a,b) = ( n_ab·键对中位 + m·φ先验 ) / ( n_ab + m ),  m = SHRINK_M = 3.0

```

**逐特征语义与系数**（预测 = 基准 × 各乘数; 基准 = 全零外推 l 66.1 / r 60.3ms;
系数来源 `实验/实验-gap特征系数表.py`, 当前快照）:

| 维 | 语义（机制） | 左手 | 右手 | 依据/备注 |
|---|---|---|---|---|
| \|Δ行\| | 手不挪动, 但指群整体要上下重新成形 — 移多远（不论方向）| **+11.0%**/行 | **+11.0%**/行 | 全表最稳, 两手逐位同 |

  带来的系统偏移）。**阈值必须乘性自适应**：
  ```
  margin(n) = exp( z · 1.253σ · √(1/n + 1/n_ref) )      z=3.46（族错误率 ≈5%）, σ 由窗口内数据估计
  ```
  **固定 margin=1.0 不是判据**（零假设下恒约 50% 越线，任何样本量都救不了——§6.2-6）。
  参数：`--window`（默认 **0 = 全量**；窗口 1000 时每组合样本永远够不到 n_min，一个都判不了）、
  `--n-min`（默认 20）、`--n-min-iso`（默认 10，孤立样本天然更少）、`--metric`
  （默认 `spread` = ld−fd 成形难度；可切 `occ`）、`--margin auto|<float>`（默认 auto）、
  `--mode`、`--iso-importance`（默认 0.5 = 1:2）、`--ref pooled|sdf`（默认 pooled）、
  `--z`、`--dry-run`、`--selftest`。
  1 键组合 spread ≡ 0 → 两层都不参与（语义正确：单指无成形难度）。
  报告列 = 综合比值 / n_eff / 阈值 / 各角色 n 与比值 / 标记（含剔除理由）。
- **动态生效**：脚本改写 `组合排除表.txt`（分段: `# [difficulty]` / `# [quota]` / `# [manual]`;
  两个判据各写自己那段、**互不覆盖**, 手工条目保留）+ `组合降权表.txt`（软降权 ③）,
  工具每 200 试次**同时重载** → 采集中即时生效，无需重启（3 键组合被拒绝排除）。
- 排除组合若为**拼读并击在用**（如 qg = 声介 ru）, 脚本会提示（仅供参考: 本项目是通用模型,
  **不承担方案的覆盖约束**; 该方案只是模型的一个用量, 2026-09-30 用户决策）。
- 判据常量按数据分布复核；每组合暴露量可由数据文件离线重构，作为学习效应协变量。

#### 4.4.2 判据 B：配额选码（三层阶梯）

**需求**（与判据 A 不是同一件事）：单手组合空间 79 = 78 + 唯一 3 键组合；78 = **15 单键 + 63 双键**。
方案单手最多 **60** 个码位 ⇒ 从 78 里取 ≤60，希望**采集早期**就把"肯定不会被用"的组合停掉
（省采集人力）。这是通用模型的一个**用量**，模型本身不承担任何方案的覆盖约束（2026-09-30 用户决策）。
判据 A 回答"是否显著慢于同角色组合总体中心"（剔几个由显著性决定，可能 0 个也可能 30 个）,
判据 B 回答"**是否肯定进不了前 60**"（要淘 18 个，由配额决定）⇒ 形状不同，不可互相替代。

```
排序量 = occ 综合比  θ_c = exp( Σ_r w_r·log(med occ_{c,r} / med occ_{参考,r}) / Σ_r w_r )
         （occ = 整击占用 lu−fd; w = 同角色 1击:2击 = 1:2 权重; 段位效应在配对差里抵消;
           参考 = --ref pooled = 同角色、同键数（2 键）组合总体中心, 不依赖 sdf）

三层阶梯 —— 证据越足、动作越硬 (2026-09-30 起 ① 不再自己硬剔):
① 配额切分 (名单): 按 θ 升序取前 45 名保留; 不可排名者**不判不动**但占保留名额
   ⇒ 名额 ≤0 时本次不切 (数据不足时切 = 掷硬币); 割线两侧 gap vs 噪声 (z_for(名次数))
   显式报"可辨/不可辨"
② 硬剔 (不可逆; --eliminate): 有 ≥K 个组合**显著优于**它 (K = 45) ⇒ 确定出局 → 写排除表
   纯两两比较 (与参考水平无关); 序贯审阅按 Bonferroni 收紧 z = z_for(1953 对 × --looks)
   (1953 对 1 次 → z=4.05; 判据 A 的 3.46 是为 189 单元定的, 不能拿来反复偷看)
③ 软降权 (可回滚; --soft-weight, 默认 0.25): 疑似出局 → 采样权重 ×系数 → 写降权表
   疑似 = 严格割线 (n_eff ≥ --n-min=20) ∪ **宽松割线** (n_eff ≥ --soft-n-min=8)
          ∪ 支配者带 (支配者 ≥ K − --soft-margin=40), 再减去已硬剔的
   软层门槛刻意更松: 硬剔不可逆 ⇒ 要强证据; 降权只是少采一点、随时能回滚 ⇒ 弱证据即可提前减预算
```

- **① 与 ②/③ 的关系（v2.19 口径变化）**：① 只产出**名单**; 谁真被停采由 ②（硬剔）与
  ③（降权）决定 ⇒ 不写 `--eliminate` 时**排除表 [quota] 段为空**, 名单里那 18 个全部只降权。
  这正是"先降权、确定后再硬剔"的阶梯, 避免不可逆地砍掉一个只是"点估计排后"的组合。
- **两档证据强度**（合成自测, 植入 18 个真慢 1.6×）: ② 在 n=20/角色 时 18/18 全中（z=4.05）;
  ③ 用宽松门槛同样 18/18 全中, 且**已硬剔的不再进降权集**（阶梯不重复计）;
  数据不足时**两者都不发生**（连宽松门槛都排不满 18 个 ⇒ 一个也不动）。

- **为什么排序量必须是 occ**（2026-09-30 实测, `实验/实验-方差分解.py` 可复现）:

  | 量 | 中位 | σ_resid | 组合份额 | 两两可辨 (n=20/角色, z=3.46) |
  |---|---|---|---|---|
  | **occ 整击占用** `lu−fd` | 127ms | **0.19** | **42.1%** (p=0.005) | **1.30×** |
  | spread 成形难度 `ld−fd`（判据 A 用） | 8.1ms | 0.87 | 15.3% (p=0.030) | 3.34× |

  `spread` 是"两个 120ms 级时刻之差"的 8ms 小量 ⇒ 相对噪声巨大; σ 比 4.6 倍 ⇒
  要同等排序分辨率, spread 需要 **~21 倍样本** ⇒ **用 spread 做的配额切分在 3000~8000
  试次内几乎淘不动任何人**（`实验/实验-配额淘汰可行性.py` ① 有对照行）。
  occ 的语义是"这个组合实际花掉的时间"（成本）, 正是"值不值得进方案"要问的;
  代价是它含 hold 成分、且与下一击有重叠（闸门）——采样随机化了后续上下文, 逐组合平均不受影响。
- **单键默认全留**：单键 `spread ≡ 0`（单指无成形难度, 判不了）+ 一级字/简词必需
  ⇒ 配额落在双键: **63 留 45、淘汰 18**（合计 15 + 45 = 60）。
- **合成自测**（`--selftest`, 植入 18 个真慢 1.6×）: ① 切掉的 18 个全中真慢, 割线
  1.45× vs 噪声 1.04× ⇒ 可辨; ② 确定出局 18 个全在真慢集合内、**误淘 0**; ③ 软降权 18/18 全中
  （宽松门槛）; 数据不足时一个都不切不降权; 同一份真难度若改用 spread 排 ⇒ 割线 1.02× vs
  噪声 1.20× ⇒ **不可辨**。
- **实测能力**（`实验/实验-配额淘汰可行性.py`, 合成 + 本机 σ/τ）: n=20/角色 时能"确定"淘掉
  ≈**3/18（occ）vs 0.2/18（spread）**; n=50/角色 → 6.1 vs 1.3（z 已含 Bonferroni）。
  **早期动作的收益主要是省采集人力, 不是提高选码精度**（同预算下最终 45 的正确率基本持平）
  ⇒ 想提精度就把省下的预算投给第 45 名附近的边界组合。**② 的能力上限**（同脚本外推）:
  每角色 n = 100/200/400/1600 → **8.9/11.2/12.9/15.4** 个确定出局 ⇒ 用尽可行预算也到不了 18,
  边界那 2-4 个只能靠 ③ 收尾（"确定"要 Bonferroni 强证据, 而真跨度 τ=0.17 下第 45/46 名的
  真差距只有 ~1%）。
- **样本量阶梯（闭环模拟, 2026-09-30; `实验/实验-新口径样本量.py`）**: 判据输出接回采样器,
  48 条独立链、审阅间隔 500 试次, 真值 τ=0.17 / σ=0.19（前者是唯一反推量; 敏感性见脚本）:

  | 里程碑（单手） | 试次/手 (中位) | 90% 分位 |
  |---|---|---|
  | ③ 软降权启动（凑满 18 个 ⇒ 最早能省预算） | 1,000 | 1,000 |
  | ① 名单出现（割线 18 个, 真前 20 无一误伤） | 1,500 | 2,000 |
  | ② 首个"确定出局"（且 0 误伤） | 1,500 | 2,650 |
  | ① 63/63 全部可排名 / 割线相邻两轮 J≥0.8 | 2,000 / 2,500 | 2,500 / 3,500 |
  | ③ 降权集精准 ≥80%（真后 18 占比） | 2,000 | 3,000 |
  | **保留码 occ 全达 ±5%** | **2,000** | 2,500 |
  | 全部 63 个 occ 达 ±5% | 2,500 | 2,500 |
  | 保留码 occ 全达 ±3% | 5,500 | 6,000 |
  | 保留码 occ 全达 ±2% | 11,000 | 11,650 |

  采样率实测 ≈ **17-19 个 occ 样本/1000 试次/组合**（三角色合计）⇒ n_eff 门槛 6/23/63/142
  对应 ±10%/±5%/±3%/±2%（中位组合 ~300/1200/3300/7400 试次; 要求"63 个全部"时因离散 ×~1.7）。
  `--n-min 20` 恰好对应相对 SE 5.3% ⇒ **"能进 ① 名单"与"occ 已知到 ±5%"是同一个门槛**。
- **③ 的启动时点（闭环实测, 重要）**: 降权集在 1000 试次时只有 **~78% 正确**（1500 试次 58%,
  2500 试次 85%, ≥4500 试次 94%）⇒ 早启动会误伤到后来要保留的码, 而这些码的样本量恢复不过来。
  `--soft-n-min 8`（默认, ≈1000 试次开动）vs 不降权对照: 保留码 ±5% **晚 50%**、±3% 晚 27%、
  63/63 可排名晚 50%、③ 精准晚 25%; 改成 `--soft-n-min 20`（与 ① 同时启动）后: 保留码 ±5%
  **+0%**、① +0%、③ 精准 +0%（只有"全部 63 个"类指标变慢 —— 那正是被放弃的组合）。
  ⇒ **已落地为写表门禁**（见下条）: <~2000 试次/手 只出名单, 不写表。
- **写表门禁（v2.20, 用户 2026-09-30 决策）**: 判据 B 在 **① 可排名双键 < 90%（放行线 ≥57/63,
  ≈2000 试次/手）** 时**拒绝写 `组合排除表.txt` 与 `组合降权表.txt`**（两张表保持原样, 含手工段）;
  报告与 `--dry-run` 照常输出（名单随时可看）。门禁 = `并击公共.quota_write_gate`
  （判据常量 `QUOTA_WRITE_RANK_FRAC = 0.90`）; `--force` 越过（打印警告, 后果自负）。
  为什么用"可排名比例"而不写死试次数: 它与采样速率/手无关, 语义就是"名次不再是掷硬币";
  实测放行点 (3000 行合成数据 63/63) 与闭环模拟的 ~2000-2500 试次一致。
  判据 A（difficulty）不设门禁（它本来就有 n_eff + 自适应阈值双闸）。
- **边界不可精确命中（不是缺陷）**: 63 个双键的真难度是连续谱, 第 45/46 名的真差距 ~1%,
  而 n_eff=20 时可辨 ~20% ⇒ **任何可行预算都切不出"精确的 18 个"**（要 ~11k 样本/组合,
  ≈70 万试次/手）。可达成且有决策意义的目标: **真前 20 一个都不被切**（48 条链 × 每个审阅点
  实测恒为 0）+ 割线集的真难度均值 = 理想割线（实测到 3 位小数相同）。
- **左右对称（v2.21）：剔除单位该是"镜像对"而不是"单只手"**。并击方案普遍用左右手对称的
  组合→编码映射（同一指形承担对应码位）, 而判据 B 现在是**逐手**判的（各自 pooled 参考与 n_eff）
  ⇒ 两手名单不必一致。量化（`实验/实验-左右对称剔除.py`, 2000 次重复; τ=0.17, σ=0.19）:

  | 每手 n_eff | τ_h（左右真偏差） | 逐手独立: 分裂对数 / 对称可用码位 | 对级判定: 码位 / 同规模损失 |
  |---|---|---|---|
  | 20 | 0（完全对称） | **4.0 对 / 41.3** | 45 / 0.19% |
  | 20 | 0.05 | 5.0 对 / 40.1 | 45 / 0.25% |
  | 20 | 0.10 | 7.0 对 / 38.1 | 45 / 0.31~0.41% |
  | 50 | 0.05 | 4.0 对 / 40.9 | 45 / 0.13~0.14% |

  · **关键**: 分裂不是"左右手解剖差异"造成的 —— **τ_h=0 时照样分裂 4 对**, 因为割线附近名次
    间距 ~1% 而单手 SE 5.3%（n_eff=20）⇒ 两手在边界处几乎独立掷硬币。**逐手独立 ≡ "任一手进
    割线就淘汰"**（并集）, 所以在"必须对称"的方案里它**白丢 4-6 个码位（45 → 41）**。
  · **三条路线**: (A) **对级判定**（镜像对当一个判定单位: 证据两手合并, 或排序取两手较慢者）
    —— 恒给满 45, 同规模损失 0.2-0.4%, **单手数据时自动退化为今天的口径**, 无风险;
    (B) 逐手并集 —— 对称但只有 41 个码位, 不划算; (C) **允许非对称映射** —— 每手各取自己最好的
    45, 零位置损失（代价是记忆/教学成本, 非时间成本）; 现方案已 86% 走在这条路上。
  · **守卫层**（合并为主 + 任一手有强证据则剔）只在 τ_h 大时才需要: τ_h=0.10 时"取劣"比"合并"
    好 0.1%（0.31% vs 0.41%）, τ_h≤0.03 时两者无差。注意"取劣"有 +0.56s 的上偏（会抬高 ② 的
    支配者计数）, 所以 ② 仍该用合并估计。
  · **是否真不对称可测且便宜**: 镜像配对采样（限制池、同对两手相邻采）→ 配对差 Δ=左−右 的
    方差分量检验: **63 对 × 每手 20 样本 ≈ 1660 试次**可检出 τ_h=5%（功效 96%）; 每手 10 样本
    ≈ 830 试次检出 8%（99%）; 只标定 16 对 ≈ 420 试次检出 6.4%（80%）。
  · **结构事实**（已进 `并击公共`: `MIRROR_KEY / mirror_combo / pair_id / mirror_pairs` + 自测）:
    镜像 = 键盘**列 9−col**, 左手 78 组合 ↦ 右手 78 组合**双射**, `sdf ↔ jkl`; 现方案在用组合
    左 51 / 右 44, **镜像成对 44（占左侧 86%）**, 仅左用 7 个（`as dx es gc gx gz qg` 无右手镜像）。
  · **已落地（v2.22 用户决策）: 双手交集 + 左右 1:1 采集**（见下条）。
- **双手交集（v2.22, 用户决策: "要剔除的组合只能是双手差组合的交集"）**: 方案的左右手可用组合
  必须对称 ⇒ 判据 B 的动作集 = **两手"差组合"集的交集**（按镜像对对齐全, 命中就**两侧一起**写表）;
  只手差的对只报告不动; 只手无数据 ⇒ 交集空 ⇒ 本次不动（这正是必须同时采两手的原因）。
  量化（`实验/实验-左右对称剔除.py` ④, 每手各切 18）:

  | 每手 n_eff | τ_h | 交集对数 | 只手差（不动） | 交集命中"真该淘" | 设计排序损失 |
  |---|---|---|---|---|---|
  | 20 | 0 | **14.3** | 3.7 | 95% | 0.26% |
  | 20 | 0.05 | 13.1 | 4.9 | 94% | 0.30% |
  | 20 | 0.10 | 11.1 | 6.9 | 92% | 0.31% |
  | 100 | 0 | 16.2 | 1.8 | 98% | 0.05% |
  | 200 | 0.05 | 14.3 | 3.7 | 97% | 0.04% |

  · 交集远大于"随机 18∩18 ≈ 5"的直觉: 因为**两手共享同一个组合难度**（估计相关 ~0.9）⇒
    14/18 的对两手都判差; 只手差的 3-7 对正是边界处"一次掷硬币"的产物, 不动为妙。
  · **能淘几个是数据驱动的**（不设固定 18 指标）: 样本越多交集越大, 左右越不对称交集越小。
  · **设计排序**（对称映射下挑 45 个码位）按**较差的那只手**（max = 慢手门控）升序; 同规模损失
    0.03-0.31% ⇒ 与理想接近。交集之后剩 ~49 对候选 ⇒ 设计只需在"只手差"的 3-7 对上做人工取舍。
- **左右 1:1 增补混采（v2.22, 用户决策; v2.23 起为唯一模式）**: 把姊妹项目"2/3/4 码混采"的机制
  （每试次按比例抽类型 + 各类型独立计数池 + `1/(n+1)` 增补）中的**类型换成手**:
  `采集-并击当量.py`（无开关; v2.23 起不能再固定单手）,
  每试次按累计欠账抽边（`hand_probability`, 单侧概率 ≤0.82）⇒ 还清历史欠账后稳在 1:1,
  且**两侧始终交错**（练习效应对称）。**总采集量 = 2× 单手阶梯**（两手都要各自达标, 写表门禁取
  最差手）。手内协议不变（混采比 1:4、结构权重、多样性、降权系数）。
  · 效果自测（`--selftest`）: 自 1000:0 欠账出发, 3000 试次后收敛到 **48.4%**:51.6%,
    且每个 20 试次窗口两侧都出现。
- **参数**：`--soft-weight W`（默认 0.25; 0 = 关闭 ③）、`--soft-n-min`（默认 8）、
  `--soft-margin`（默认 5）、`--pair intersect|hand`（默认 intersect = 双手交集）、
  `--force`（越过写表门禁）; 表文件 = `组合降权表.txt`
  （`组合<TAB>系数`; `# [manual]` 段手工保留; 每轮**全量重写** ⇒ 疑似恢复后自动撤销）。
- **待办（后续）**：硬剔与降权都是**采样侧**动作, 不改动已采数据; 覆盖约束已取消
  （2026-09-30 用户决策: 本项目是通用模型, 不承担任何具体方案的声韵母覆盖;
  "拼读并击在用"只作提示, 不作限制）。

### 4.5 训练与评估协议

- **数据池**：稳定期（分类型，§3.5）→ `error=0` 行 → **散布 MAD 单侧围栏 + 值围栏**（v4，对齐姊妹项目"任一段超限弃整行"的语义：occ 桶 = 角色 × 键数，gap 桶 = n1'×n2'，3 键计 2）。围栏拦的是散布正常的注意力断档型超长间隙，再剔 ~2%。**模型只用稳定期数据**（当量 = 当前状态语义）；换用全量池会同时改变当量语义与精度（§5.2-56）。
- **划分**：**trial 级**（`RandomState(2024)` 按类型 80/20，自测断言无跨侧试次）；**段级划分禁用**（同试次的段共享上下文 ⇒ 泄漏）；划分版本号随快照打印。
- **门禁单元**：口径级改动一律在**组合级留出**（整组合移出训练集）上判定——实测只有它有分辨力（CI 宽 l≈1.5 / r≈0.5ms），段级单元连 +2ms 的真效应都测不出（§5.2-9）。
- **四宫格**：段-occ / 段-gap / 试次-1击 / 试次-2击，各带基线；外加**结构消融**（三段分解 vs 直接预测 wc）。
- **指标**：MAE 与 R² **并列报**——R² 对测试集随数据增长的重洗敏感（实测可单独跳 +0.55 而 MAE 只动 2.5ms），**跨快照只比 MAE**。
- **σ 口径**：判据与阈值一律用**单元内 σ**（`并击公共.sigma_within_log`）；pooled 会把组合/角色/会话差异算进噪声（阈值偏宽 5~7%）。
- **确定性**：无随机流扰动（固定种子）；神经/嵌入臂 `torch.set_num_threads(1)` + `manual_seed`，逐种子训练后**全体平均**（无 best-of 选优、不抽签）。生产默认估计器 `--model shrunk`（纯线性先验 + 收缩），**不需要 torch**。

### 4.6 组装与应用

```
T(语料) = Σ_词 闸门感知合成（同时起手，2 击词闭式见 §4.1）   ← **默认纯击键时间**（v2.15）
          【可选】+ ERR_COST_MS × Σ_词 期望 episode 数   ← --cost 打开（见 §4.2）

  报数口径: 主报**纯击键时间**（默认），并注明"不含错误项（转录错误以 R1 读取型为主）";

### 5.3 几何特征与 occ 的关系

几何特征不重写（import 槽位序口径）; 数据 = 稳定期池 + 围栏, occ 已消除角色差异。利用"双键 63 = 9 列形态 × 7 行对, 每格恰 1 组合"可做精确闭合的二因素分解; 9 列形态 = 9 个合法指对（同指两列 (3,4) 非法）, 故"列形态"读作"指对"。

指对是 occ 的第一因素, 且两手一致（名次 ρ=0.72）。方差占比: 列形态 / 行对 / 交互 = 左手 **89.6 / 4.1 / 4.2 %**、右手 **42.7 / 52.4 / 2.6 %**。含小指的指对全慢、不含小指的全快, 两个分布不重叠: 含小指整体左手 **+23.1%**、右手 **+9.9%**; 指对极差 **1.37(l) / 1.22(r)**。最慢 / 最快指对: 左手 `小+中` ×1.221 / `中+食外` ×0.888, 右手 `小+无` ×1.115 / `中+食内` ×0.911; `小+中` 比最快指对慢 **37%(l) / 22%(r)**。这与手工硬剔完全吻合 —— 6 对手工排除正是两个最慢指对类（`wa/o;` `sz/l/` `qs/pl` = 小+无 ×3; `ax/;.` `qd/pk` `ac/;,'` = 小+中 ×3）。

行对只在右手重要（下排/上排 = 左手 0.99、右手 1.22）; 行项必须逐手估, 与现状逐手拟合一致。连续几何: 离小指越远越快（列质心 β 左手 −13.8 / 右手 −8.9 ms/单位）, 右手越靠下越慢（行质心 +9.7 ms/行）, 列跨度 +5.5（左）。旋转角方向对 occ 几乎无影响（三水平都在噪声内）—— 与 gap 侧相反。

可加性成立: 指对 + 行对解释组合间方差 **94–95%**, 交互仅 4.2/2.6%, 支持 27×5 结构分解与 occ 可加先验; 交互项虽超测量噪声但两手互不相关（ρ=0.21）⇒ 属组合特异难度（具体键位手感）, 非对称几何, 不能靠镜像共享。

描述与外推存在张力（留一整个指对出去, 预测其 7 个组合）: 类别格在样本内解释更多（R² 0.718 vs 几何 0.527, 左手）, 但外推只有连续几何能补 —— MAE **l 10.3 / r 5.6ms** vs 常数臂 **l 14.2 / r 9.2**（"行对"臂在左手 ≡ 常数）。⇒ 外推未见指对（先验的本职）用几何, 拟合已见用类别格。

### 5.4 两击之间几何变化量与 gap 的关系

口径全部 import（gap = `build_samples`; 变化量 = 槽位序几何; 生产 φ 直接调用 `phi_gap`）。前提: 键对空间 79²=6241 而只见到 **332/584** 个（**1.02 样本/对**）⇒ 只能特征级; 置信区间 = 键对聚类 bootstrap。

变化量的核心只有"行向位移": |Δ行| 0→2 在控制负载与两侧绝对位置后仍净加 **+19…+37ms**, 且"零位移"比水平量预期**快 14–16ms**（左手 0 → −16ms、|Δ|=2 → +22…+37ms; 右手 0 → −14ms、|Δ|=2 → +19…+26ms）。位移块在"两侧水平几何"**之上**的 R² 净增量 **+0.069(l) / +0.061(r)**（整个位移块 0.08–0.13, 几乎全来自行）。

列向位移无净效应（Δ列质心全在 ±11ms 内、CI 跨 0）⇒ 生产 φ 的 `dc/|dc|` 在描述上是可议项。Δn'（键数变化）零增量（**−0.0000 / +0.0000**）⇒ 负载应写成四格水平 `1→1/1→2/2→1/2→2`, 不是变化量。

Δ旋转角 / Δ|旋转角| 有小而实的额外信息（在 φ v5 之上增量 **+0.0134 / +0.0067**; 描述上"反转最慢"两手同形）—— 与留出单元的小胜/略负一致 ⇒ 维持内插基定位, 不进口径。

gap 基本无向: 右手 38 对双向可见, log[gap(a→b)/gap(b→a)] **+0.8% [−6.3%, +8.8%]**（ns）⇒ 有符号项贡献很小, 主要由 |Δ| 与负载驱动; 左手只 10 对不可判。坐标口径上, 生产 φ 的 `dc` 用原始键位列（固定空间坐标）, 槽位序才镜像一致; 列向效应很弱（斜率 ±1%, CI 跨 0）, 尚不足以判, 但跨手共享先验前必须先定坐标。上列 R² 全为 in-sample（容量对照: 同维数随机重排 R² 0.019–0.033）⇒ 外推结论仍以留出 gap（未见键对）为准: 只有列数（负载）块在未见键对上不倒退。

### 5.5 顺逆指（人手结构版）

定义: 顺逆指 = 一击 2 键的行差是否符合人手结构（小/无/中在食指之上、小/无在中之下、小在无之下、同排 = 顺; 其他跨行 = 逆）⇒ 自然深度序 **中指 > 无名 > 小指 > 食指**, 与冻结的 `dir_slot` 并存; 独立复核 72 跨行组合 **0 不一致**。每手 **顺 45 / 逆 18**（旧槽位序口径 18/18/27）, 12/36 跨行组合与旧标相反。

occ 侧假设不成立: 边际那点"顺更快"全来自"同排并入顺"; 逐指对（消掉指对主效应）**4/9(l)、5/9(r)** 顺更快（p=0.75/0.50）, 平均 **+0.9% [−3.9,+5.8] / −1.0% [−4.5,+2.7]**; 模型 ΔR² 仅 **+0.0012 / +0.0031** 且两手系数符号相反; 留一指对外推 MAE **16.7→16.8 / 10.6→10.6**（零改善）; 两手逐指对差值名次相关 **ρ=−0.53**（n=9）。方法论要点: 旧旋转角是"行对"的函数 ⇒ 在"指对 + 行对"可加基底里被完全吸收（ΔR² 恒 0）; 新顺逆指是"指对 × 方向"的交互量, 才有独立自由度, 但仍不值得进 occ。

gap 侧部分成立: 顺逆块 ΔR² **+0.0225(l) / +0.0236(r)**（大于 Δrot 的 +0.0164/+0.0073）, 但两者高度重叠（在"位移 + Δrot"之上只剩 +0.0010/+0.0009）⇒ 同一类方向/倾斜信息。控制负载与两侧水平几何后**唯一显著格 = 顺→逆**: **+15.2ms [+8.7,+21.8]**（左）/ **+9.8ms [+2.9,+16.5]**（右）, 两手同号 ⇒ 载体是**转移方向**而非单组合顺逆（"变向/同向"二分会抹平信号）。若将来保留, 落地形式应是 **gap 的 Δ 项**, 且须过配对 bootstrap。

### 5.6 跨击影响：一段时长是否受另一击组合影响

生产口径 `log occ = base(组合) + offset(角色)` 在角色内 **additive** ⇒ 隐含"段时只由自身组合决定"。识别设计两方向严格对称: 自己 = `own`、另一击 = `other`（S1: own=A; S3: own=B）; **own 内中心化**消掉自身组合的全部效应（基数/键数/角色）⇒ 残差只含另一击与噪声; 主估计 = **池化两水平之差**（聚类 bootstrap 以 own 组合为簇）, 另有逐 own 配对中位作稳健对照。可识别性: 每手 2 击 ok **1092 / 1060** 试次; 79 组合都当过 A 与 B; 每个 own 组合见过**中位 12–13 个** other 伙伴（范围 5–27）; own 内另一击跨单双键者 **60–65/79**, 跨有/无共键者 73–75/79 ⇒ 该问题在现有数据上可检验。

**S1 ← 另一击成立且稳健**: 三个估计量一致（池化 / 配对中位 / 截尾均值）, 两手同号。全量: **+4.8ms [+2.4,+7.3]**（左）/ **+7.7ms [+5.4,+9.9]**（右）; 逐 own 配对中位 +3.6ms（48/77）/ +7.0ms（63/79）; 稳定期池（n≈392/660）更强: **+6.5ms [+3.7,+9.0] / +6.1ms [+3.8,+8.6]**。负对照（打乱另一击标签）4 单元全跨 0。

**S3 ← 另一击方向一致但更弱**: 全量 **+3.5ms [+0.4,+6.8]**（左）/ **+5.6ms [+2.5,+8.5]**（右）显著, 逐 own 配对中位 +4.4ms（48/76）/ +6.6ms（49/78）; 稳定期池左手不复现（+0.3ms [−3.8,+4.0]）、右手边缘（+3.0ms [−0.7,+6.5]）⇒ 记为未确认。

另一击几何（行/列位置）不稳: 控制键数后 S1 两手皆无; S3 的"另一击在上排"效应换池会翻正负（不稳）、"另一击在小/无列 → 本段 +2…+3ms"两手同号但只在全量显著 ⇒ 方向存疑, 不下结论。另一击"身份"去掉键数后只剩 S1 一侧的弱信号（稳定期 1.19/1.26, p=0.075/0.045, 4 单元里只 2 个显著）; 左手的 S3 身份信号在稳定期池完全消失（1.70 → 0.95）⇒ 判为练习期/状态混杂, 不是稳定状态属性。

生产含义（4 种子 trial 留出）: 加"另一击大小（单/双）或键数"只降 MAE **−0.14…−0.19ms**（CI 多跨 0）; 加"另一击身份（79 水平）"反而 **+0.57…+0.76ms** 变差（(A,B) 对平均只 **1.06 次**观测, 估不出来）。对照自身组合基线 MAE 16.6/16.5（S1）· 19.5/18.4（S3）。量级算术: 水平偏移方差 ≈5ms²、段内 trial 间 σ≈20ms ⇒ 期望 MAE 降幅 ≈ Var/(2σ) ≈ **0.13ms**, 与实测一致 ⇒ 统计真实、工程可忽略。机制: S1 = 首按→末放（**按住时长**）, 它在"另一击更长时更长" ⇒ 与**预放置/提前起步被吸进本段**相符, 也正是"手独立 + 预放置吸收度"那条**不可实测残差的实测形态**（段级 ±2.4ms, 对应单词级 ~5–10ms）。

附带（小样本, 仅登记）: 两击**同一组合**时本段 **−21…−35ms**（n=10–12/手）⇒ 手形复用的大效应, n 太小且真实词几乎不出现, 不作结论。

### 5.7 gap 段：全量池、跨键几何与残差形态

harness 交叉验证: 本脚本的 `v5` 参考与生产 `phi_gap` **逐位一致**（6241 键对 0 不一致）, 稳定期段-gap 复现生产 **l 13.8 / r 19.0**; MLP 自实现（三形态）在残差模式下与生产 `EmbedModel` **自检差 0.000ms**（8 个配置全过）。

全量池（不取稳定期）不让 MLP 翻过生产（trial 留出, 3 种子平均）: 稳定期 左手 shrunk **13.78** / MLP 15.14（+1.36）、右手 shrunk **18.99** / MLP 19.24（+0.24）; 全量 左手 **27.13** / MLP 29.72（+2.59）、右手 **22.73** / MLP 24.39（+1.66）⇒ 两池两手**全输**, 左手在全量池下差距还**拉大**; 两臂绝对 MAE 都大幅变差（池混入练习态, 且被评试次来自练习期）。全量池还改「当量」语义: 时间留出偏差 左 **+5.3 → +42.2ms**、右 **+4.6 → +22.9ms** ⇒ 学的是"练习史平均", 不是当前状态。

跨键几何用门禁单元 = 组合级留出（4 抽; 留出段 l 1580 / r 1586; 留出组合参与的键对全"未见"⇒ 评的是**纯 φ 先验**）。基准 `v5` = **26.05ms（左）/ 20.37ms（右）**。新块"键对级几何"（对 c1×c2 **全部键对**算 min/均/max |Δ行|、|Δ列|、最小/最大距离, 无需键序）: 右手**显著**（`v6+键对几何` **−0.57 [−1.14,−0.08]** 4/4、`v6−dc+键对几何` **−0.60 [−1.12,−0.16]** 3/4）, 左手加在 v5 上无帮助（+0.07 [−0.17,+0.29]）、只在换掉负载维后才 −0.34 ⇒ 两手不一致; 唯一两手都有支持的是 **`v6` 负载四格**本身（−0.22 [−0.40,−0.04] / −0.22 [−0.48,+0.03] 4/4）。最佳组合 `v6+键对+Δrot`（20 维）两手 4/4 同向（8/8）: **l −0.51 [−1.02,+0.03] / r −0.52 [−1.07,−0.05]**, 但左手 CI 跨 0; 24 维全块反而变差（−0.40 / −0.42, 维度稀释）。净增益 ≤0.6ms 且单侧/单单元 ⇒ 不进口径, `v6+键对+Δrot` 记为下次复评候选第一位。

机制: 键对几何 7 维里 5 维已被现行 φ 线性解释 **0.41–0.94**（平|Δ行| 0.94、min|Δ行| 0.76、min距离 0.78 等）, 整块净增量 in-sample R² **左手 +0.006 / 右手 +0.026** ⇒ 左手 v5 的负载维（n1'/n2'）已把键对几何吃掉, 只有右手吃得下。坐标口径: raw 键位列 vs 槽位序对单手 ridge 是**恒等变换**（单列符号翻转不改 λ‖w‖², 预测逐位相同, 实测 `v6 ≡ v6s`）⇒ 该口径只对跨手共享先验有意义。MLP 的亏损与特征集无关: 6 个特征集下 Δ(MLP − 纯先验) = 左 **+0.49…+2.59** / 右 **+1.16…+3.18**, 换更好的几何也不缩小 ⇒ 网卡在**稀疏身份项**（(A,B) 平均 1.06 次观测）。

残差形态有实质作用, 不能去掉（特征集 = 最强 `v6+键对+Δrot`）: `absolute`（直接 pred = exp(net)）相对 `shrunk` 纯先验 MAE 全面变差 **+15.77**（左·稳定）/ **+3.23**（左·全量）/ **+9.17**（右·稳定）/ **+4.76**（右·全量）, 即 +2.2…+15.8ms（稳定期最惨, 先验最强时丢先验代价最大）; v5 特征集下同样（l 稳定 +9.48 / l 全量 +2.15 / r +4.97 / +2.39）。`prior_in`（先验只当输入）优于"完全去掉", 但仍比残差结构差 **+0.09…+3.81ms**（仅 l 全量 −0.51 在噪声内）⇒ 关键不只是"先验可用", 而是**"预测 = 先验 × 修正"这个乘性结构**本身。

共键细分（数据侧分布）: **不共键 78.5/79.4% · 1共键 19.9/19.3% · 全共键 1.6/1.3%**。1共键内"该共键移动距离"的三种读法（A = 共键外两键行差 |row(a)−row(b)|; B = c1∪c2 并集行跨; C = 共键自身行号）**两手符号都相反** ⇒ 该 0/1/2 位移没有两手一致的信号; 原始 gap 中位差异（如 l A 档 125.0/141.3/159.2）主要被"跨行 ⇒ 更慢"解释, 而 φ 的 Δ行已有。模型增量 ≈ 0: 门禁单元把二值 `same_key` 换成共键四分（−0.04 l / +0.00 r）、再叠位移 A/B/C（−0.05…+0.11）**全部 CI 跨 0**; trial 留出 −0.05…+0.12 ⇒ 共键细分不进口径。唯一大效应 = **全共键**（两击同一组合）相对先验**快 26/12ms**（n 仅 18/14）—— 与 §5.6 的"同组合手形复用 −21…−35ms"互证, 但生产已由**键对中位收缩**自动吸收, 不必单独建模。

## 6. 讨论

### 6.1 局限性

- **单用户口径**（与串击一致）：当量是个人量，跨用户不迁移；本文全部读数来自单人当前熟练状态。
- **双边合成残差不可实测**（§6.2-1）：因不采双手同击数据，合成只能取**下界方向**（只可能低估），不可测的是"手独立"与"预放置吸收度"两条假设（闸门项本身已证恒 0）。
- **姿态边界**：空格不并入击（简词/二级字首选的"音节 + 空格"击未采，评估时常数折算）；数字键不采（三级字右手数字部首同样常数折算）；单手 3+ 键的速录式并击不在域内。
- **n ≥ 3 击词口径未定**：中段击的角色偏移未测，`compose_word` 直接拒绝 n ≥ 3（不静默给错值）。
- **错误项**：当前不计入当量——采集本质是照图转录，实测错误 88% 是读取型 R1（§4.2），不代表真机使用时的错误率；真机错误率需连续文本录入日志才能测（与词间中断同源）。
- **池内漂移**：稳定期池仍在随水平上升而漂移（§5.1 报数口径 ④），绝对 MAE 偏悲观。

### 6.2 未来工作

1. **双边合成残差不可实测**（2026-09-07 起）：both 采集移除后，无法用双手实测核对
   该合成的残差 —— 但**不可测的不是闸门项**: v2.33 (2026-10-04) 已证明闸门项在实测表上
   **恒为 0**（全枚举 550 万真实词 Δ≡0, §4.1; 守卫 = `实验/实验-分段max合成.py --part 3`），
   剩下不可测的是两条假设: **手独立**（单手表的 occ/gap 直接搬到双边击里的那一手）
   与**预放置吸收度**（被挡手是否在闸门开后立即按键）→ 合成仍取**下界方向**（只可能低估）。
   M3 可用拼读并击真实跟打记录（`打字练习记录.xlsx`、160 分钟速度曲线）做整体绝对值校准；
2. **错误项已暂不计入（v2.15, 2026-09-24）**，故其常数的不确定性**当前不影响结论**；
   完整口径与敏感性扫描保留在 `组装当量表.py --cost`（0/400/782/1000/2000，实测 2 击词
   395/462/527/563/732 ms）。**待解的是真机错误率**：转录任务的 P_err（88% 为 R1 读取型）

   附带未知项：连续键位图可读性（从未试采）；
3. **起手异步**：模拟按同时起手（§4.1），真实打字的起手异步未测（单侧、量级小）；
4. **分段结构的净收益**：三段分解（+闸门合成）vs 直接预测 wc（M2 结构消融判定）；
5. **段位特征的粒度**：孤立/词首/词尾/中段 + 是否需分左右手位（先例：击键测速角色片）；
6. **剔除判据的参数复核**（`spread` vs `occ`、margin、n_min、窗口长度、参考占 5% 是否
   够稳）+ **孤立角色是否也要设限**（当前只用上下文 S1/S3；1 击词用到某组合时其孤立
   难度也相关——报告已附孤立比值列，可据此决定是否加 `iso` 角色）；
   **2026-09-30 补充结论**（排序量与配额, 见 §4.4.2）：`spread` vs `occ` 的问题**已定案** ——
   判据 A（难度异常）继续用 `spread`; **选码排序（判据 B）必须用 `occ`**（σ_resid 0.19 vs 0.87,
   组合份额 62.6% vs 27.7%）; 78→60 的配额 = 单键全留 + 双键留 45; "能确定淘几个"随样本量
   缓慢增长（n=20/角色 ≈4/18）, 收益主要是省人力;
   **2026-09-24 已定量分析**（`实验/实验-剔除样本量.py`，结论：**先改判据形式, 不是攒数据**）：
   · **`margin=1.0` 不是判据**：零假设下 `med(组合) > med(参考)` 恒约 50% 概率成立
     ⇒ 无论多少样本都会剔掉约一半被测组合（模拟：n=21 误剔 10.4 个、n=55 误剔 27.2 个，
     对半分 Jaccard 仅 0.29~0.31）；该值只能当 `--dry-run` 的**排序**看；
   · **现状三参数互不兼容**：`window=1000` 时每组合仅 ~7 样本 < `n_min=20`
     ⇒ 一个组合都不会被判定（旧锚口径下实测：sdf 样本 1/0 个，整角色跳过）。
     **2026-09-30 起参考改为同角色组合总体中心**（pooled, n≈2000）⇒ 参考不再是瓶颈,
     门槛只剩"每组合自身 n_eff ≥ n_min"；判据 B 的可排名门槛同此（`--n-min`）；
   · **覆盖度**（复刻真实采样器，三角色）：角色门槛 (iso 10 / S1·S3 20) 要到
     **~5000 试次/手**才普遍满足；3000 试次时 iso med 10 (59% 达标) / S1 21 (59%) /
     S3 19 (48%)，综合 n_eff ≈ 50；5000 → med 16/35/33 (100%/100%/98%)，n_eff ≈ 84；
     8000 → 26/55/52，n_eff ≈ 133。**参考池同时刻 n = 全体 2 键组合样本之和**（S1 约数千段）,
     3 键组合 sdf 与普通 2 键同比例（8000 试次时 ~30/53/60，不再是 ×5 的 66/116/175）；
   · **阈值必须乘性自适应**：`margin = exp(z·1.253σ·√(1/n+1/n_ref))`，z=3.46 控 189 单元
     族错误率 ≈5%，σ≈0.87 由窗口内数据估计。
     ⚠ 写成 `1 + z·SE` 是**错的**（z·SE 大时严重低估阈值 → 误剔数高数倍）：本项分析
     2026-09-24 曾用线性式，误剔 4.8/63；改乘性后 0/63（合成自测）；
   · **分辨率**（乘性阈值，含共享三角色的 n_eff）：
     | 试次/手 | 单角色 S1 阈值 | 综合 n_eff | 综合阈值 | 可检出真比值 (80% 功率) |
     |---|---|---|---|---|
     | 3000 | 2.28 | 50 | 1.71 | 单角色 2.79× → **综合 1.94×** |
     | 5000 | 1.89 | 84 | 1.51 | 2.21× → **1.67×** |
     | 8000 | 1.67 | 133 | 1.39 | 1.88× → **1.50×** |
     ⇒ 共享三角色（n_eff ≈ 2.4×）把阈值压低 17~25%，分辨率 2.8× → 1.9×；
     要分辨 ~1.4× 仍需 n≈100（~15000 试次/手）；
   · **单键组合在 `spread` 口径下永不触发**（`spread ≡ 0`）——语义正确（单指无成形难度），
     不必修；要判其占用只能换 `occ`，但 `occ` 混 hold 节奏策略、不能当难度量；
   · **一击参与判定（已落地，v2.13）**：角色扩为 `iso`/`S1`/`S3`，三层口径见 §4.4；
     根本原因（原实现为何零贡献）= 判定只枚举 `("S1","S3")` 且经 `hand_segments`
     （对 1 击行返回 `{}`）取数，孤立数据只进了报告列「孤立比」、不进 verdict。
     **实测水平差**（n=69/82/84）：孤立 med 6.5 (p75 9.5) < S1 8.7 (16.3) < S3 12.9 (20.1)
     —— 定义相同（ld−fd）但水平与上尾系统性更低 ⇒ **不可直接合并求中位**（合并有偏：
     锚的段位配比与普通组合不同，合成自测系统性低估 ~5%；正确做法 = 同角色配对，
     段位效应在差值里抵消）；
   · **iso 最薄**：其每组合 n 约为 S1 的一半 ⇒ 用 `--n-min-iso 10`（而非 20）才能
     在 ~3000 试次起用上它；这正是"1击:2击 重要性 1:2"与"样本量 1:2"自然吻合之处。
   · **新口径的样本量阶梯（v2.20, occ 排序 + 三层阶梯, 闭环模拟）**：见 §4.4.2 的表 ——
     **1500 试次/手** ①名单出现 / **2000-2500** 判据 B 完整可用（63/63 可排名 + 割线稳定 +
     ③ 精准 ≥80% + ② 有确定出局）/ **2000** 保留码 occ 全达 ±5% / **5500-7000** ±3% /
     **11000-13000** ±2%；**② 硬剔饱和在 ~10-15 个**，边界靠 ③ 收尾。
     上面这张表是 spread 时代（判据 A / 角色门槛）的口径；配额与排序一律以 **occ** 为准
     （σ 0.19 vs 0.87 ⇒ 同等分辨率 spread 需 21 倍样本）。
   · **v2.22 起总采集量 = 2× 上表**（左右 1:1 增补混采; 两手各自达标, 写表门禁取最差手）。
7. T_SYNC 校准与散布分布（M1）；组合难度是否需**转移条件化**（当前按角色 S1/S3 聚合，
   未再细分前击——窗口内平均；若残差显示前击效应显著再分层）；
8. 空格入击（拇指通道，简词/首选击）、数字部首——常数折算或 v2 扩展；
9. 单用户口径（与击键测速一致：当量是个人量，跨用户不迁移）。

## 7. 结论与应用

- **组装层**（`组装当量表.py`）：段当量 = 时值（默认纯击键时间；`--cost` 打开错误项）→ `产物/段当量表.npz` + `产物/总当量-并击.txt`。输出 = 1 击词（孤立占用）与 2 击词（三段合成）的期望耗时**ms 原值**（不归一化）。
  ```
  T(语料) = Σ_词 闸门感知合成（同时起手）
            2 击词: max_h( occ(c₁) + gap + occ(c₂) )      ← 闸门项恒 0（§4.1、§5.2-37）
            1 击词: max_h occ_h(c)                        ← 手不参与某击则取 0
            【可选】+ ERR_COST_MS × 期望 episode 数        ← --cost 打开（§4.2）
  ```
- **键位重排评估**：组合空间全覆盖（79/手）⇒ 新方案的组合查表即得，**无需重采**；击对全空间表不必预先枚举（组装时按词内击对在线求值）。
- **方案对比**：与姊妹项目串击同用户、同 ms 单位 ⇒ 并击"两击 4 码"的理论提速 vs 散布/同步/错误折损，可在同一尺度上量化。终局产出 = 拼读并击整方案时间当量 + 与拼读双拼的同口径对比报告。
- **现状边界**：模型与组装链已可运行（含合成自测与 `--cost` 扫描），但**当量表仍是先验主导**（段级样本不足）——定表判据是 §3.6 的样本量阶梯。

## 附录 A. 脚本命名规范

- **共用模块必须是无连字符的合法标识符**（Python 不能 `import` 连字符名）：`并击公共.py`（口径唯一源：组合空间 / TSV / 三段量 / 阈值与 σ / 错误成本常数）与 `采集核心.py`（引擎语义与 GUI 组件唯一源）
- 一次性决策实验脚本在结论写入本 README 后归档（先例：特征系列 / 剔除系列 / 显示协议系列）
